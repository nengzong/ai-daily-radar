## 🎯 值得做的机会

### 1. 企业 LLM 用量治理 / AI FinOps —— 今日优先级最高

亚马逊用 Claude 给网站批量补作者信息，5 个月烧掉约 180 万美元、约 6000 亿 token、超预算 860%，项目最终没有上线；Meta、Uber、OpenAI 内部都出现过类似的成本失控。文中给出的关键数字是：**仅 26% 的企业对自身 AI 成本具备全面可见性**。

**为什么值得关注**：这是一个定义得非常清楚的空白——预算护栏、按团队/项目配额、异常烧钱实时告警、token 成本归因看板。技术门槛低（本质是网关 + 计量 + 看板），但买单意愿正在被真金白银的事故教育出来，且天然属于企业服务赛道。

🔗 https://www.qbitai.com/2026/08/469010.html

### 2. 把 FM / 楼宇运维知识打包成 Agent Skill 包

今日 GitHub Trending 上 `addyosmani/agent-skills`（当日新增约 779 star）和 `google/skills`（约 481 star）同时上榜——Skills 正在成为 Agent 领域新的分发单元，且 Google 已经下场做标准化。

**为什么值得关注**：大厂下场意味着通用领域的窗口会快速关闭，但也意味着格式和生态被免费铺好了。把设备台账规范、工单 SOP、能耗诊断流程这类领域知识打包成 Skill 分发，是当下成本极低、卡位效果好的动作。

🔗 https://github.com/addyosmani/agent-skills ｜ https://github.com/google/skills

### 3. Channels SDK（CopilotKit）——Agent 接入层不用自己写了

MIT 协议开源 SDK，把任意已有 Agent 接进 Slack、Microsoft Teams、Discord、Telegram，并自动渲染各平台的原生 UI。Show HN 118 分。

**为什么值得关注**：做企业 Agent 时，「怎么让用户在已有的协作工具里用起来」往往比模型本身更耗工。这个 SDK 直接消掉这块工作量。它的商业化结构也值得抄：SDK 自部署免费，平台连接服务与企业自托管收费。

🔗 https://github.com/CopilotKit/channels-sdk

### 4. 用 WiFi CSI 做非接触式空间占用感知（ESP32-C5，硬件成本 9 元起）

一位开发者用 9 元起的 ESP32-C5 开发板，靠 WiFi 信道状态信息（CSI）做非接触式人体状态监测，一夜实测精度很高，已开源并顺带卖硬件——整个过程「用 Codex 一天搞定」。

**为什么值得关注**：直接命中 FM 场景。不需要红外或毫米波传感器，用现成 WiFi 设备就能判断「房间是否有人、活动水平如何」，可用于会议室占用率统计和空置区域能耗控制。更重要的信号是：AI 已经把这类信号处理的实现门槛打到了「一天」。

🔗 https://www.v2ex.com/t/1233022

### 5. 做一套 FM 领域的 Agent 能力评测基准

法律 AI 头部公司 Harvey 开源了 `harvey-labs`——Agent 在法律工作中的能力评测基准（当日新增约 47 star）。

**为什么值得关注**：垂直行业头部开始用「公开评测基准」来定义行业标准和话语权。在 FM 领域做一套公开基准（工单派单准确率、故障诊断、能耗归因），是低成本建立行业影响力的路径，且顺带解决自己的 Eval 问题。

🔗 https://github.com/harveyai/harvey-labs

### 6. 企业 Agent 规模化落地的四步路径

行业观察指出：2026 年预计 40% 的企业应用将嵌入任务型 Agent（2025 年不足 5%），摩根大通的 Agent 系统已覆盖 3 万+员工，腾讯云企业 Agent 客户数同比增长超 100%。文中总结的落地路径是：先做高频且规则明确的场景 → 建企业语义层 → 把目标拆成原子任务并在关键节点设人工校验 → 重新定义人机边界。

**为什么值得关注**：这四步几乎可以原样套到楼宇运维（工单派发、巡检、能耗异常处置）——尤其是「先高频且规则明确」和「关键点人工校验」两条，正是 FM 场景 Agent 最容易翻车的地方。

⚠️ 该文来自搜索兜底，发布日期未能确认在 8/7–8/9 区间，引用前建议点开核对。

🔗 https://www.huxiu.com/article/4880667.html

## 💰 赚钱案例

### 7. VideoToNotes —— 全 Serverless 的轻量付费 AI 工具

把视频/音频转成结构化笔记。技术栈：React + Cloudflare Workers + Soniox 转写 + DeepSeek 生成，**按分钟积分制收费**，新用户送 20 积分。

**为什么值得关注**：一个可复制性极强的样本——无自有模型、全部调 API、成本随用量线性变化，所以积分制定价既直观又不会亏钱。做小工具变现时，这套技术栈与定价组合可以直接照搬。

🔗 https://www.v2ex.com/t/1233083

## 💡 产品灵感

### 10. AgentConnect —— 不逼用户迁移，直接在 Slack 里 @ Agent 派活

开源的多 Agent 协作平台，在 Slack / Telegram / Discord / GitHub 里直接 @ 任意 Agent 分派任务；角色、模型、记忆、工具、权限可逐个配置，**支持私有化部署（代码与消息不出内网）**。今日 PH 107 赞。

**为什么值得关注**：与 Agent/BOT + 企业服务方向高度重合。两个设计选择值得抄——不要求用户迁移到新 App，以及把「数据不出内网」做成一等能力，这正是企业客户最关心的两点。

🔗 https://www.producthunt.com/products/agentconnect

### 11. prime-agent —— 长任务自治 Agent 的骨架（今日 Trending 第一）

自我改进的编码/长任务自治 Agent，当日新增约 2.5k star，MIT 协议。两个抽象值得研究：**RLM**（把上下文当变量、工具当可编程函数，跑在常驻 Python REPL 里）和 **Continual Harness**（把补充提示词、记忆、可复用子 Agent 规格做成可持续修订的持久状态）。

**为什么值得关注**：长时运行 + 断线不丢会话 + 后台任务心跳——这正是设备巡检、长周期能耗诊断这类 FM Agent 需要但通常自己搭不好的骨架。

🔗 https://github.com/PrimeIntellect-ai/prime-agent

### 12. code-graph-rag —— 图谱化 RAG，可直接平移到楼宇领域

面向 monorepo 的知识图谱 + RAG，可跨语言查询、理解并修改代码库。

**为什么值得关注**：楼宇领域的「设备—系统—空间—工单」本来就是天然图结构。这类推理——「这台冷机故障会影响哪些区域」——纯向量检索根本答不好，图谱 RAG 的工程范式可以直接借鉴。

🔗 https://github.com/vitali87/code-graph-rag

### 13. Quote/0 电子纸看板 —— 极小屏幕逼出的信息减法

为 152×296 的黑白电子纸设备做了 11 块信息看板（F1 赛程、积分、结果），聚合 ESPN / Jolpica F1 / OpenF1 接口，比赛期间 15 秒轮询、最短 60 秒推送。

**为什么值得关注**：「环境化信息设计」的好样本。极小的屏幕强制做信息减法，这套方法论可以直接迁移到楼宇运维大屏和工位屏——不是把系统搬上去，而是只留三五个真正值得瞥一眼的指标。

🔗 https://sspai.com/post/113158

### 14. Elevators —— 电梯科普页拿下 Hacker News 全站第一（1676 分 / 415 评论）

一个关于电梯如何工作的互动科普页面，今日 HN 全站最高分。

**为什么值得关注**：一个与 FM 沾边的意外信号——楼宇机电设备题材做成优质可视化内容，能拿到极高的自然传播量。做楼宇/设施领域的内容获客时，「把楼里的机电系统讲得好玩」是已被验证的流量入口。

🔗 https://john.fun/elevators
